# Librera Next — техническое задание на UI/UX-редизайн

**Версия:** 1.0, 10 ноября 2026 г.  
**Назначение:** передать coding-агенту для реализации внутри существующего форка Librera.  
**Визуальный референс:** `index.html` (или автономный `Librera_Next_Interactive_Prototype.html`).  
**Машиночитаемые токены:** `design-tokens.json`.  
**Приоритет:** внешний вид и UX меняются; существующая работа читалки, форматные движки, импорты и данные не ломаются.

## 0. Роль и границы задачи

Ты — senior Android Java engineer и UI/UX engineer. Изучи **реальную** структуру репозитория, прежде чем менять архитектуру. Текущий UI: нативные Android Views, Activity/Fragment, XML и программно созданные View; базовый язык Java, сборка Gradle, AndroidX, RecyclerView. В проекте используются локально WebView и JavaScript (включая Foliate.js для EPUB); весь интерфейс **не** является WebView. Нельзя переносить приложение на Compose, Kotlin или переписывать ридер с нуля.

Требуется выполнить **инкрементальный** редизайн, используя существующие механизмы навигации, хранения, библиотеки, декодирования, выделения текста и чтения. Если структура форка отличается от предполагаемой — адаптируй план после аудита. Не выдумывай имена классов, пути ресурсов и зависимости, пока не проверишь их в репозитории.

Отдельно сохранять пользовательские данные: историю, прогресс, избранное, закладки, аннотации, порядок сортировки, источники файлов, форматы, настройку PDF, поворот страницы и параметры рендеринга.

**Не подменяй Android-приложение HTML-прототипом.** HTML нужен только для визуального референса.

## 1. Продуктовые принципы

1. **Content first:** основной экран показывает книги и быстрый вход в чтение. Команды второстепенны.
2. **Progressive disclosure:** базовые действия видимы, редкие — в bottom sheets и вложенных категориях. Пользователь не видит одновременно двадцать чекбоксов.
3. **Книжная эстетика:** кремовая бумага и древесно-коричневые акценты; без чисто белых огромных поверхностей в светлой теме.
4. **Три ручных фиксированных пресета:** Cream, OLED, E-Ink Color. Хранить выбор между запусками.
5. **Консистентность:** одна система цвета/форм/отступов во всех Activity, Fragment, Dialog, PopupMenu и WebView-элементах.
6. **E-Ink — отдельное поведение**, а не просто переключение цвета. Никаких ненужных анимаций, теней, прозрачностей, непрерывных обновлений.
7. **Доступность:** контраст, текстовая иерархия, 48dp touch target, TalkBack, поддержка масштаба шрифтов и сохранение прогресса чтения.

**Специальные запреты:**

- **OLED:** не использовать чистый `#FFFFFF` как цвет обычного текста. Не эмулировать приглушённость посредством `alpha=.35`. Использовать непрозрачный `#D4CEC6` для текста и `#9B938B` для подписи. Фон **именно страницы** `#000000`; у карточек допустим `#161616`.

- Явно задать цвета для всех типов `TextView`, заголовков, вкладок, чипов, `RecyclerView.ViewHolder`, popup и WebView-обвязки. Проверить `android:textColor`, `textColorHint`, tint и disabled-color.

Токены семантические. Не копировать hex по разным Java-классам и XML. Сделать единый источник цветов: Android resources + тему/overlays + helper для programmatic views. Material 3 стандартные роли (`colorPrimary`, `colorOnPrimary`, `colorSurface`, `colorOnSurface`, `colorOnSurfaceVariant`, `colorOutline` и surface-container-roles) маппить из нашей палитры. Нестандартные роли (`readerBackground`, `featuredContainer`) оформить собственными attrs/resources.

## 3. Геометрия и визуальный язык

Размеры в **dp**, шрифты — в **sp**; не переносить браузерные px напрямую. Начальные рекомендуемые значения:

| Элемент | Значение |
|---|---|
| Горизонтальный отступ основного содержимого | `16dp` (на планшете `24–32dp`) |
| Вертикальные промежутки секций | `24dp` |
| Расстояние между строками списка книг | `6–8dp` |
| Нижняя плавающая навигация | высота `64–72dp`; отступы сбоку `12dp`, снизу `12–16dp` **плюс системный inset** |
| Радиус навигации | `24–28dp` |
| Радиус основных карточек | `20–24dp` |
| Радиус карточек настроек | `16–20dp` |
| Радиус чипов / action button | `16–22dp` / pill |
| Радиус верхней плавающей панели ридера | `20–24dp` |
| Радиус верхних углов bottom sheet | `24–28dp` |
| Размер иконки | `20–24dp`, без избыточной детализации |
| Минимальная интерактивная область | `48×48dp` (независимо от нарисованного размера иконки) |
| Заголовок экрана | `28sp`, medium/bold `700–800` |
| Заголовок секции | `18–20sp`, semi-bold |
| Название книги в списке | `14sp`, semi-bold |
| Автор / вторичный текст | `12–13sp` |
| Подписи/метаданные | `11–12sp`, но не уменьшать ниже читаемого предела на E-Ink |
| Текст книги | пользовательский, ориентир `18sp`, serif для художественного текста |
| Межстрочный интервал книги | пользовательский, старт `1.6–1.7` (не навязывать PDF) |

Плавающие панели отделяются от контента цветом `surface` и тонким `outline`. Тени допустимы умеренно в Cream и OLED, полностью отсутствуют в E-Ink. Не использовать gradient, glassmorphism, blur, translucent background или тяжёлые backdrop-effects. Панели не должны перекрывать последнюю строку книги и управляться inset-ами.

## 4. Экран «Библиотека»

### 4.1 Верхняя область

- Слева лаконичный wordmark «librera next.» (если брендинг в форке другой — сохранить имя приложения).
- Справа поиск и сортировка. Нет трёх рядов кнопок и меню на всю ширину.
- Заголовок «Моя библиотека» и подзаголовок «N книг · M в процессе чтения». Данные — реальные из существующей БД, не хардкод.
- Подзаголовки контрастные: Cream `#62564B`, OLED `#9B938B`, E-Ink `#49574C`.

### 4.2 «Продолжить чтение»

- Одна крупная featured-card: реальная обложка (или placeholder), автор, название, глава/страница, прогресс и одна кнопка «Продолжить».
- Выбор книги — последняя открытая / последняя активная согласно существующим данным.
- Прогресс показан и цветом, и числом `%`.
- Если истории нет, карточку скрыть и компактно показать «Добавить книгу» или onboarding.
- Не дублировать большую карточку несколько раз подряд.

### 4.3 Полка книг

- `RecyclerView` с `ListAdapter`/`DiffUtil` если совместимо с текущим подходом.
- Переключатель **список ↔ сетка** с сохранением состояния.
- Чипы: «Все», «Читаю», «Прочитано»; дополнительные фильтры в bottom sheet (форматы, авторы, серии, язык, метки, теги).
- Строка списка: обложка ≈ `64×94dp`, название до 2 строк, автор, формат, прогресс и контекстная кнопка (favorite / меню).
- Контекстное меню книги: открыть, в избранное, информация, переместить в коллекцию, удалить из библиотеки (с обязательным различением «удалить запись» и «удалить файл» и подтверждением при удалении файла).
- Поиск: поле появляется на месте управляющей строки, реальная фильтрация; отдельное действие «Очистить».
- Сортировка: «Недавно открытые», «Название», «Прогресс», дополнительные существующие виды сортировки сохранить во вложенном меню.
- Для пустой библиотеки, нет результатов и ошибок доступа сделать полноценные empty/error states.

### 4.4 Навигация

Основная плавающая скруглённая нижняя панель содержит четыре пункта:
1. **Книги** — библиотека.
2. **Полки** — коллекции, пользовательские папки и источники.
3. **Избранное** — избранные книги.
4. **Настройки** — категории конфигурации.

«Недавние» и «Закладки» не удалять из возможностей! Перенести в библиотечные фильтры/отдельные представления или контекст чтения так, чтобы их можно было открыть не более чем за 2–3 действия. Иконки одноцветные в стиле Material Symbols (VectorDrawable), 20–24dp. Активный пункт имеет `selectedContainer`.

## 5. Экран «Чтение»

- **Основной сценарий:** только страница с текстом, без постоянно закреплённых верхней и нижней панелей.
- Касание по центру переключает видимость панелей; ввод, выбор текста, выделение и ссылки должны иметь приоритет над жестом скрытия.
- При показе интерфейса появляется скруглённая верхняя floating-toolbar: «Назад», укороченное название, «Закладка», `Aa`, «Ещё».
- Внизу плавающая полоса прогресса: процент, `текущая/всего`, полоса прогресса, предыдущая/следующая страница.
- Экран не скачет при показе панелей. Читательская область остаётся на месте; элементы навигации накладываются, учитывая безопасные отступы.
- `Aa` открывает `BottomSheetDialogFragment`: размер текста, шрифт, межстрочный интервал, поля, выравнивание, отступ абзаца, переносы (если применимо к EPUB), сохранение для книги/по умолчанию.
- «Ещё»: оглавление, поиск по книге, список закладок, заметки, ориентация, режим листания, режим чтения, движок — по контексту.
- Индивидуальные настройки конкретной книги не должны без спроса менять настройки всех книг.
- Элементы доступны TalkBack; на аппаратных клавишах листание по существующим настройкам работает как прежде.
- Использовать реальную логику страниц/процентов. Не считать страницу из `scrollTop`, если движок имеет собственную нумерацию.

### 5.1 EPUB / Foliate.js

- Для EPUB отправлять токены `readerBackground`, `onSurface`, настройки типографики, размера и интервалов **через поддерживаемые API текущего Foliate.js / слой интеграции**.
- Не менять содержимое книжного документа глобальными CSS-хакерами, нарушающими структуру, изображения, ссылки и выделения.
- Согласовать тему WebView-контейнера с темой Activity во время загрузки: не должно быть короткой белой вспышки в OLED.
- Сохранять положение (locator / CFI / имеющийся в форке формат) при изменении шрифта и темы. Важный acceptance-test: после переразметки позиция чтения не прыгает в начало книги.

### 5.2 PDF / MuPDF

- PDF остается визуально корректным в цвете документа. Не применять к PDF принудительно тёмный инвертирующий фильтр только потому, что выбрана OLED-тема UI.
- Тёмный PDF — отдельная опция, только если это корректно поддерживает используемый рендерер.
- Фон панелей PDF следует теме, но содержимое страницы следует выбранному пользователем PDF-режиму.
- Не ломать зум, прокрутку, crop, поворот, аннотации, поиск и выделение текста.

## 6. Экран «Настройки»: прогрессивное раскрытие

Главный экран настроек показывает **ровно пять категорий**, каждая с иконкой и однострочным описанием:

### 6.1 Внешний вид
- Три пресета: Cream, OLED Black, E-Ink Color.
- Предпросмотр карточкой, активная тема явно отмечена.
- Параметры отображения панелей, плотность UI, отображение обложек.
- Опциональный системный режим — отдельная будущая функция; он не перезаписывает три фиксированных пресета.

### 6.2 Чтение
- Типографика по умолчанию.
- Управление жестами/касаниями.
- Видимость панелей, статусной строки, прогресса.
- Разделение EPUB/FB2 (reflowable) и PDF/DJVU (fixed-layout) параметров.
- Существующие дополнительные параметры — внутри «Дополнительно» или раскрывающегося блока, но не удалены.

### 6.3 Библиотека
- Источники: Download, добавление каталога через Storage Access Framework, внутреннее и внешнее хранилище — по существующей поддержке.
- Индексация: обновить, автоскан, исключения, кеш миниатюр.
- Форматы — в «Фильтры форматов»; не показывать сразу большой список чекбоксов.
- Не запрашивать разрешения на файлы без пользовательского действия, не терять доступ к ранее выбранным URI.

### 6.4 Синхронизация
- На этапе чистого редизайна создать **место в навигации**, не изображать несуществующий облачный механизм как работающий.
- Предусмотреть backend-neutral API для прогресса, закладок, аннотаций и настроек. Никакого хранения файлов в стороннем облаке без явного согласия.
- Если в репозитории уже есть собственная синхронизация — интегрировать существующую, не создавать дубликат.
- Будущий провайдер, например WebDAV или Yandex Disk, рассматривается отдельной задачей с конфликтами и merge-стратегией.

### 6.5 Дополнительно
- Движки и форматы: MuPDF, Foliate.js и прочие фактически используемые в форке.
- Производительность/кеш, совместимость, режим E-Ink, логирование, информация о приложении.
- Сохранить путь к редким старым настройкам, возможно через отдельный Advanced Preferences screen.

## 7. Тема OLED — отдельные требования

- Для страницы чтения использовать `#000000`; для листов настроек и плавающих панелей `#161616`.
- Основной текст `#D4CEC6`, подписи `#9B938B`, прогресс `#A7B9A9`.
- Не использовать большие ослепительно белые поверхности, яркие иконки и цветные gradients.
- Состояние экрана при запуске, переходе между Activity/Fragment и открытии bottom sheet не должно кратковременно становиться белым.
- `windowBackground`, цвет splash/launcher transition, status/navigation bars и фон WebView должны использовать согласованные ночные значения.
- Не делать все элементы полупрозрачными: особенно текста и пиктограммы. Использовать заданные непрозрачные цвета.
- Проверь на реальном OLED на минимальной яркости. Учитывать, что фактическая воспринимаемая яркость зависит от устройства, подсветки и размера светлых областей.

## 8. E-Ink Color — Meebook M8C

- Цвета E-Ink темы из таблицы, читательский фон `#FFFFF6`, текст `#1C2820`.
- Удалить/отключить в приложении **анимации открытия меню, движения bottom sheets, ripple, elevation/blur, skeleton shimmer, бесконечные спиннеры, параллакс, плавный скролл** там, где это допустимо. Не подменять только системный animation scale: предусмотреть стиль компонентов E-Ink без анимаций.
- Все навигационные элементы имеют явную границу и статическое активное состояние; нельзя обозначать выбор только цветом.
- Тени отключены. Предпочитать однотонные surface, контуры `#829187`.
- Обложки оставить цветными, но необязательный режим уменьшенной насыщенности допустим как настройка; не считать, что все цвета будут различимы на Kaleido 3.
- Избегать автоматического обновления элементов при каждой прокрутке. Debounce тяжёлые операции списка. Использовать `DiffUtil`/частичную перерисовку.
- После полной смены темы/ориентации/длинной прокрутки может понадобиться полное обновление экрана; API и режимы обновления **выяснить по доступному SDK именно Meebook M8C**. Нельзя выдумывать универсальный Android E-Ink API или вызывать Onyx-специфичный SDK без проверки совместимости.
- Если нет поддерживаемого SDK обновления, реализовать прежде всего чистый UI без анимаций; аппаратное управление вынести в интерфейс `EInkRefreshController` с no-op реализацией и адаптером для поддерживаемого устройства.
- Оставить ручное действие «Полное обновление страницы» только если аппаратное поведение действительно доступно.
- Крупные зоны касания для чтения одной рукой, возможность скрыть панели полностью.
- В физическом тесте проверять ghosting при листании, скорость появления bottom sheet и визуальную различимость selected/disabled.

## 9. Реализация на Android Views / Java / XML

### 9.1 Подход

1. Сначала изучить существующую навигацию, Activity/Fragment и ресурсы тем: `themes.xml`, `styles.xml`, `colors.xml`, `dimens.xml`, programmatic views.
2. Оценить, как внедрить Material Components **без ломания существующей темы**. Предпочтительно `Theme.Material3.DayNight.NoActionBar` при совместимости. Не обновлять зависимости без необходимости.
3. Создать общий слой design tokens: семантические attrs/resources, shape appearance, typographic styles. Например, `readerBackground`, `featuredContainer`, `appTextSecondary`, `appSelectedContainer`.
4. Три темы — через resources/theme overlays и `ThemeManager` на Java. Выбор хранить в существующем Preferences (или SharedPreferences, если подобного слоя нет). Применять тему до `setContentView`/инфлейта. При необходимости `Activity.recreate()` с предварительным сохранением состояния.
5. Не превращать HTML-прототип в WebView-библиотеку. Java/XML-рекомендуемый состав: `RecyclerView`, `MaterialCardView`, `MaterialToolbar`, `MaterialButton`, `MaterialChip`, `BottomSheetDialogFragment` и другие совместимые компоненты Material.
6. Для темизируемых programmatic views не вшивать hex: использовать `MaterialColors.getColor` или `TypedValue` / resolved theme attrs.
7. Для экранов с `WindowInsetsCompat` учитывать статус-бар, системный gesture inset и cutouts, особенно для плавающих нижних панелей и bottom sheet.
8. При изменении темы сохранять текущую книгу, позицию, открытые табы, сортировку и скролл библиотеки.

### 9.2 Предлагаемые модули (имена условные)

- `ui/theme/ThemeManager.java`: чтение пресета, переключение, применение overlays.
- `ui/theme/ThemeTokens.java` или XML attrs: семантические токены.
- `ui/library/LibraryFragment.java`: новый layout над существующим data layer.
- `ui/library/BookAdapter.java`: единый layout для списка и сетки.
- `ui/reader/ReaderChromeController.java`: видимость и позиции плавающих панелей вокруг существующего рендера.
- `ui/reader/ReaderAppearanceBottomSheet.java`: параметры читательской страницы.
- `ui/settings/SettingsRootFragment.java`: пять категорий.
- `ui/settings/*SettingsFragment.java`: настройки по категориям.
- `ui/eink/EInkRefreshController.java`: опциональная абстракция аппаратной перерисовки.

**Это не требование создать именно эти классы:** сначала сопоставь с реальным устройством репозитория, потом выбери минимально инвазивную структуру.

### 9.3 XML-ресурсы, стили и иконки

- Весь векторный UI — монохромные `VectorDrawable` в стиле Material Symbols; `android:tint` / `app:tint` через theme attrs.
- Библиотека Android Material Components использует цветовые роли M3 и умеет настраивать `BottomSheetDialog`/`BottomSheetDialogFragment` через `shapeAppearance` и overlay.
- В качестве стартовой темы рассмотреть `Theme.Material3.DayNight.NoActionBar` только если это безопасно для текущего проекта.
- Проверить пользовательские старые `TextView`/`Drawable` со светлыми фиксированными цветами; они часто становятся причиной неконтрастных заголовков после миграции.
- Для `PopupWindow`/`Dialog` явно проверить `windowBackground`, dim amount, контуры, кнопки и `textColor`.

## 10. Состояния и взаимодействия

**Обязательные:**
- Выбор Cream/OLED/E-Ink применяется в библиотеке, читалке, настройках и диалогах; сохраняется при перезапуске.
- Поиск в библиотеке; переключение список/сетка; сортировка; фильтры; избранное.
- Тап по книге открывает реальную книгу; тап «Продолжить» ведёт к позиции чтения.
- В читалке тап по незанятому тексту показывает/скрывает панели. При этом выделение текста и ссылки работают как раньше.
- `Aa` позволяет поменять размер и межстрочный интервал (для reflowable-форматов), изменения видны сразу без потери позиции.
- Настройки открываются по категориям; возврат сохраняет контекст. Пустые states и ошибки описаны и реализованы.
- На системе с навигационными жестами ничего не оказывается под системной полоской.

**Не демонстрировать как работающие без backend:**
- Облако, синхронизацию, скачивание/импорт, аппаратное обновление E-Ink, реалистичное содержимое книги и искусственный прогресс браузерного макета. В Android должны использоваться текущие реализации.

## 11. Адаптивность и доступность

- На телефоне: одна колонка, плавающий bottom-nav; нижние панели не перекрывают контент.
- На Meebook 7,8″: больше полей и плотность колонок по доступной ширине (например, двухколоночная сетка книг). Не растягивать строку книги/диалог на всю ширину планшета, если это ухудшает чтение.
- Поддержать portrait/landscape, увеличение системного шрифта, длинные названия, RTL только если существующий проект его поддерживает.
- Icon-only buttons должны иметь `contentDescription` и подходящую область касания.
- Отдельно тестировать режим TalkBack, управление клавиатурой/кнопками, контраст фокуса.
- В настройках E-Ink допускается более крупный текст подписи (`12–14sp`) ради разборчивости.

## 13. Критерии приёмки

- [ ] Все три темы доступны из UI, сохраняются после перезапуска и применяются ко всем Activity/Fragment/Dialog.
- [ ] В Cream заголовок «Моя библиотека» тёмный `#352B25`; он не становится почти белым на светлой поверхности.
- [ ] В OLED основной текст `#D4CEC6`, не `#FFFFFF`; фон страницы книги `#000000`.
- [ ] В E-Ink нет визуально заметных анимаций и теней; выбранные элементы различимы и без цвета.
- [ ] На каждом тестовом фоне обычный текст имеет минимум 4,5:1, значимые иконки минимум 3:1 (кроме нормативно допустимых исключений).
- [ ] Список/сетка, сортировка, поиск, фильтры и избранное реально работают с базой приложения.
- [ ] Продолжение чтения не меняет прогресс и открывает книгу на предыдущей позиции.
- [ ] Floating toolbar автоматически скрывается; тап, текстовое выделение и ссылки работают без конфликтов.
- [ ] Изменение `Aa` не сбрасывает EPUB locator / выбранную страницу.
- [ ] PDF не инвертируется сам по себе при выборе OLED.
- [ ] Старые настройки и форматы не утрачены, редкие перенесены в Advanced.
- [ ] Insets/gesture bar не перекрывают клавиши. Touch target ≥48dp.
- [ ] Собирается Gradle-проект; изменены только нужные модули; нет зависимости от Compose/Kotlin.
- [ ] Прогон smoke/regression: EPUB, FB2, PDF, DJVU, поиск, закладки, история, поворот, изменение темы во время чтения.
- [ ] Агент описал какие файлы изменил, как проверить, что осталось сознательно не реализовано.
